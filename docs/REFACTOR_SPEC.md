# ThreadPilot 重构规格

更新日期：2026-07-25

## 1. 产品边界

ThreadPilot 只做两件事：

1. 对话折叠
2. 对话时间线

不再提供文件夹、搜索、书签、导出、隐藏 ChatGPT 原生控件、自动滚到底部、导航左右切换、侧边距调节、性能模式等独立功能或设置。

产品判断标准：用户不离开当前 ChatGPT 对话，就能更快看懂长对话结构、找到某一轮，并压缩暂时不需要阅读的内容。

## 2. 竞品结论

调研对象：

- [AI Toolbox](https://www.ai-toolbox.co/)：单条折叠、全部折叠、快捷键。
- [AI ChatNavigator](https://extwise.com/extension/ai-chatnavigator/)：以用户提问生成实时目录、滚动时高亮当前提问、侧栏可固定和收起。
- [ChatGPT Long Conversation Toolkit](https://chromewebstore.google.com/detail/chatgpt-long-conversation/heeioiefmkfoajlaahfbicganjplkfae)：隐藏旧轮次、当前会话内定位、操作按需出现。
- [Superpower ChatGPT](https://spchatgpt.com/features/)：最小地图、逐条滚动、分支树；证明长对话需要结构视图，但其功能面过宽，不适合作为 ThreadPilot 的产品边界。

可复用原则：

- 时间线默认只显示用户提问。用户通常记得“自己问了什么”，而不是 AI 回答的开头。
- 当前轮次必须随滚动实时高亮。
- 悬停预览应先帮助确认内容，再执行跳转。
- 单条折叠与全部折叠都要提供。
- 折叠后仍保留上下文：回答摘要、长度、展开入口。
- 工具必须贴近 ChatGPT 原生界面，不能抢占主要阅读空间。
- 高级控制按需出现，默认界面保持安静。

明确不采用：

- 把功能堆进 ChatGPT 左侧栏。
- 为每个节点显示 AI 和用户两种点，制造重复噪声。
- 只有无语义圆点、无法预判内容的“迷你滚动条”。
- 通过固定像素高度粗暴截断回答。
- 大量永久设置项。

## 3. 信息模型

### 3.1 Turn

一轮对话由一个用户消息及其后紧邻的助手消息组成。

```text
Turn
├── id
├── userMessage
├── assistantMessage
├── promptPreview
├── answerPreview
├── answerLength
├── collapsed
└── active
```

缺少助手消息时，该轮仍应进入时间线，并显示“正在生成”状态。

### 3.2 稳定标识

优先使用 ChatGPT DOM 中的 `data-message-id`。缺失时使用“对话 URL + 角色 + DOM 顺序 + 文本指纹”生成会话内稳定键。

折叠状态只在当前页面会话期间保存，不上传内容，不持久化消息正文。

## 4. 对话折叠

### 4.1 默认行为

- 只自动折叠助手长回答，用户消息保持完整。
- 默认阈值：回答正文高度超过 `420px` 或纯文本超过 `1,000` 字符。
- 自动折叠只作用于首次发现的长回答。
- 用户手动展开后，不得因 DOM 更新再次自动折叠。
- 正在生成的回答不自动折叠；生成结束后再判断。

### 4.2 折叠呈现

折叠态必须保留：

- 助手身份与原生消息工具区域。
- 前两行正文预览。
- 状态文案，例如“已折叠 · 1,204 字”。
- 明确的“展开”按钮。

不得：

- 只留下空白块。
- 遮住代码块顶部语言标签。
- 移除 ChatGPT 原生复制、反馈或重试控件。
- 用渐变遮罩覆盖可点击内容。

### 4.3 操作

- 单条：展开 / 收起。
- 批量：使用时间线轨道外的独立按钮，根据当前状态执行折叠全部或展开全部。
- 快捷键：`Alt + C` 切换全部折叠状态。

批量“折叠全部”只折叠已完成的助手回答；短回答也可以被手动批量折叠，但默认自动折叠仍只针对长回答。
批量操作前记录当前问题相对滚动容器的位置，操作后恢复该位置，避免时间线当前轮次跳变。

### 4.4 可访问性

- 控件使用原生 `button`。
- `aria-expanded` 与实际状态一致。
- `aria-controls` 指向被折叠内容。
- 键盘焦点可见。
- `prefers-reduced-motion` 下禁用过渡。

## 5. 对话时间线

### 5.1 默认结构

- 每一轮只生成一个位置刻度，标题来自用户提问。
- 刻度顺序与 DOM 中用户消息顺序一致，并按消息在滚动内容中的真实位置映射。
- 当前刻度与跳转落点共用同一条安全线：滚动容器顶部下方 `84–112px`。
- 时间线显示总轮数与当前位置，例如 `6 / 18`。
- 批量折叠按钮位于轨道外，点击区域不得与轨道或顶部导航按钮重叠。

### 5.2 节点内容

静止态只显示紧凑节点；悬停、键盘聚焦或拖动时显示：

- 轮次序号。
- 用户提问前 80 个字符。
- 助手回答前 120 个字符。
- 折叠状态。

### 5.3 交互

- 点击刻度：在页面或 ChatGPT 内部滚动容器中，把对应问题放到固定顶栏下方。
- 拖动滑块：连续预览，松手后跳转。
- 顶部按钮：回到滚动容器顶部。
- 底部按钮：跳到滚动容器底部。
- `Alt + N`：下一轮。
- `Alt + P`：上一轮。
- `Alt + J`：显示 / 隐藏时间线。
- 跳转后短暂高亮目标消息，帮助视线落点。

### 5.4 边界

- 只有一轮对话时隐藏时间线。
- 超长对话压缩为密集刻度，时间线不产生独立滚动条。
- 对话正在增长时增量更新，不全量重建所有事件监听。
- 窗口较窄时自动收成轨道，不覆盖正文。
- ChatGPT 路由切换后清空旧引用并重新采集。

## 6. 弹窗

弹窗只保留两个主开关和一个最小偏好：

- 时间线：开 / 关。
- 自动折叠长回答：开 / 关。
- 默认折叠阈值：紧凑 / 平衡 / 宽松，默认“平衡”。

辅助区域只显示快捷键，不再提供单独“性能模式”、位置、像素距离、原生控件隐藏、自动滚底等设置。

## 7. 代码重构边界

### 删除

- `hideOfficialNav` 及所有原生导航探测 / 隐藏代码。
- `side`、`navOffset` 及对应布局分支。
- `autoScrollToBottom` 及 bottom lock。
- `performanceMode` 及双重刷新策略。
- `filter` 设置；时间线固定以用户提问为索引。
- 旧的固定高度 `collapseHeight` 数值输入。
- About 页中与两项核心功能无关的说明。

### 保留并重写

- 消息角色和正文提取：保留容错选择器，改为 Turn 采集器。
- `MutationObserver`：保留一个观察器，改成批量调度和增量 diff。
- 时间线点击 / 拖动 / 键盘跳转：保留能力，重写 DOM 和状态模型。
- 折叠状态集合：保留“用户手动覆盖自动状态”的思想，改成明确的状态机。
- 本地 `chrome.storage.sync`：只保存功能开关和阈值档位。

### 新模块边界

即使继续使用无构建步骤的 Manifest V3 结构，`content.js` 内部也按以下职责分区：

1. DOM adapter：适配 ChatGPT DOM。
2. Turn store：构建、diff 和索引轮次。
3. Fold controller：自动 / 手动折叠状态机。
4. Timeline controller：渲染、激活、跳转和拖动。
5. Settings bridge：读取设置与响应变更。
6. Lifecycle：路由切换、MutationObserver 和清理。

## 8. 验收标准

### 功能

- 20 轮以上对话中，时间线节点数等于用户消息数。
- 点击任意节点能定位到对应用户消息。
- 滚动对话时，当前节点在一帧调度周期内更新。
- 自动折叠不会作用于正在生成的回答。
- 用户展开的回答不会被后续 DOM mutation 自动收回。
- 折叠全部 / 展开全部结果与所有助手回答状态一致。
- ChatGPT 对话切换后没有旧节点或旧折叠状态泄漏。

### 体验

- 时间线关闭后不残留可点击透明层。
- 在 1280px 宽视口下不遮挡消息正文和输入框。
- 触控目标最小 `32 × 32px`；主要开关最小 `40 × 24px`。
- 浅色、深色主题均可读。
- 中文和英文长文本均不会撑破布局。

### 性能

- 100 轮对话首次建立时间线不创建超过 100 个节点。
- 滚动只更新 active 状态，不重新采集全文。
- DOM mutation 合并到单次调度执行。
- 不存在持续轮询定时器。

### 隐私

- 不请求网络权限。
- 不上传、索引或持久化对话正文。
- 仅保存开关与阈值偏好。
